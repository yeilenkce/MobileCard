# 시험패스 PoC

2026 모바일신분증 아이디어 공모전에 낸 아이디어 "모바일신분증 시험패스"의 프로토타입입니다. 휴대폰을 제출하는 시험장에서도 본인 확인이 되도록, 시험 전날 발급한 일회용 서명 QR을 수험표에 인쇄하고 시험 당일 감독관 단말이 오프라인으로 검증하는 흐름을 **브라우저 안에서 실제로 서명하고 검증하며** 보여 줍니다. 서버가 없고 빌드도 필요 없는 정적 사이트입니다.

시연용 가상 데이터입니다. 실제 서비스가 아니며 정부 기관, 실존 인물, 실제 시험과 관련이 없습니다.

## 구현 범위

| 항목 | 상태 | 설명 |
| --- | --- | --- |
| 서명 생성 | 구현 | WebCrypto ECDSA P-256 / SHA-256. 발급기관 키쌍은 이 브라우저에서 생성하고 개인키는 추출 불가능한 키로 IndexedDB 에 둡니다. |
| 서명 검증 | 구현 | 감독관 단말은 패키지에 들어 있는 발급기관 공개키만으로 확인합니다. 내용이나 서명을 조금만 바꿔도 거절됩니다. |
| QR 페이로드 | 구현 | 버전, 시험ID, 시험일, 수험번호, 토큰ID, 발급시각, 만료시각과 서명만 담습니다(페이로드 39바이트, 서명 64바이트, QR 문자열 143자, QR 49×49칸). 이름, 생년월일, 사진은 없습니다. |
| QR 생성 | 구현 | 실제로 스캔되는 QR. qrcode-generator 라이브러리를 씁니다. |
| QR 읽기 | 구현 | 카메라(getUserMedia + jsQR), 이미지 업로드와 끌어놓기, 붙여넣기(문자열, 클립보드 이미지). |
| 4단계 검증 | 구현 | 전자서명, 시험·일자 일치, 유효시간, 미사용 여부를 순서대로 확인하고 한 단계라도 실패하면 이름과 사진을 보여 주지 않습니다. |
| 사진·이름 대조와 통과 처리 | 구현 | "일치, 통과"는 토큰을 사용 처리하고, 같은 QR을 다시 스캔하면 4단계에서 경고합니다. "불일치, 보류"는 토큰을 소모하지 않습니다. |
| 검증 패키지 | 구현 | 시험장 단위로 토큰ID별 이름, 생년월일, 사진을 AES-GCM(256비트)으로 암호화해 저장합니다. 토큰ID와 패키지ID를 인증 데이터로 묶어 다른 항목에 끼워 넣을 수 없습니다. |
| 시험 종료 파기 | 구현 | 패키지(키 포함), 암호화 항목, 사용 기록, 검증 이력을 지우고 저장소를 다시 세어 0건임을 화면에 표시합니다. |
| 오프라인 검증 | 구현 | 검증 중 네트워크 요청 0건(아래 "네트워크 확인"). |
| 검증 테스트 5종 | 구현 | 정상, 변조, 다른 시험, 만료, 이미 사용. 임시 키로 만든 QR을 실제 검증 코드에 넣어 기대한 결과와 비교합니다. |
| 측정 모드 | 구현 | 스캔 시작 또는 QR 입력부터 통과 처리까지의 시간을 기록하고 평균, 중앙값, CSV 를 냅니다. 기록이 없으면 "측정값 없음"으로 표시합니다. |
| 기기 간 패키지 옮기기 | 부분 구현 | 암호화된 패키지 파일과 해제 코드를 사람이 따로 전달합니다. 배포 채널은 아닙니다. |
| 모바일신분증 본인확인 | **연출만** | PIN 6자리 입력은 시늉입니다. 아무 숫자나 통과하고 실제 모바일신분증 앱과 연동하지 않습니다. |
| 발급기관 키 관리 | **미구현** | 보안 모듈 보관, 키 교체, 폐기 목록이 없습니다. 개인키는 같은 브라우저 저장소에 있습니다. |
| 시험장 단말로의 패키지 배포 | **미구현** | 발급기관이 시험장 단말에 패키지를 내려 주는 채널이 없습니다. |
| 단말 간 사용 기록 공유 | **미구현** | 사용 처리는 단말마다 따로입니다. 한 시험장에 단말이 여러 대면 한 QR이 단말마다 한 번씩 통과할 수 있습니다(테스트로 확인). 설계상 입구 단말 하나로 운영하거나 사람이 사진을 대조해야 합니다. |
| 시험 접수 연동, 수험번호 부여 | **미구현** | 수험번호는 이 브라우저 안의 순번(A-0001)입니다. |
| 단말 시계 신뢰 | **미구현** | 만료 판단은 단말 시계를 믿습니다. 시연용으로 시계를 시험 당일 09시로 옮기는 설정이 있고, 화면에 "시연용 이동"이라고 표시됩니다. |
| 고령층 대면 발급, 접근성 인증 | **미구현** | 키보드 조작과 화면낭독용 속성은 넣었지만 실사용자 검증은 하지 않았습니다. |
| 보안 점검, 현장 사용성 비교 | **미수행** | 제3자 점검이나 실제 시험장 시험은 하지 않았습니다. 측정 모드는 이후 측정을 위한 도구입니다. |

### 한계로 알고 쓰세요

- 이 PoC 에서는 발급과 검증이 같은 브라우저 저장소를 쓸 수 있어서, 발급기관과 시험장 단말이 분리된 실제 구조를 완전히 재현하지는 않습니다. 검증 코드는 패키지의 공개키와 패키지 키만 쓰도록 나뉘어 있지만, 같은 브라우저에서는 개인키와 패키지 키가 한곳에 있습니다.
- 사진 대조와 최종 통과 판단은 사람이 합니다. QR 사진을 찍어 둔 사람이 입실하는 것은 QR만으로 막을 수 없고, 사진 대조와 일회용 사용 처리로 줄이는 구조입니다.
- 카메라 스캔은 Chromium 가짜 카메라 장치로 자동 테스트했습니다. 실제 휴대폰 카메라와 조명 조건에서의 인식률은 측정하지 않았습니다.

## 실행

빌드가 필요 없습니다. 두 가지 중 편한 방법을 쓰세요.

1. `docs/index.html` 을 최신 Chrome, Edge, Safari 에서 바로 엽니다(Chrome 에서 `file://` 로 확인했습니다).
2. 로컬 서버: `cd docs && python3 -m http.server 8000` 후 `http://localhost:8000` 을 엽니다.

휴대폰 카메라로 쓰려면 `https` 주소가 필요합니다. GitHub Pages 를 쓰면 됩니다. 저장소 Settings 의 Pages 에서 Branch 를 `main`, 폴더를 `/docs` 로 고르면 `docs/` 가 그대로 공개됩니다. 이 폴더는 `docs/` 하나로 완결되므로 다른 파일은 올리지 않아도 됩니다. 아직 어디에도 올리지 않았습니다.

### 시연 순서

1. **응시자 앱**: 시험을 고르고 PIN 6자리를 누르면 제공 항목 동의 화면이 나옵니다. 체크하고 "시험패스 발급"을 누릅니다.
2. **수험표**: 종이 수험표 모양의 QR이 나옵니다. 오른쪽은 QR 문자열을 실제로 해독한 값(있는 정보)과 없는 정보입니다.
3. **감독관 단말**: 카메라, 이미지, 붙여넣기로 QR 을 넣으면 네 단계가 차례로 확인되고 사진과 이름이 나옵니다. "일치, 통과"를 누른 뒤 같은 QR 을 다시 넣어 보세요.

발급은 "시험 전날"이라고 가정하므로 시험일이 내일입니다. 감독관 단말은 시계를 시험 당일 09시로 옮겨 두고 시작합니다(상단 "단말 시각"에 표시). 실제 시각으로 돌리고 싶으면 "시험장 설정 바꾸기"에서 바꾸면 되고, 그러면 시험일이 아니어서 2단계에서 거절됩니다.

화면 녹화용으로 주소 뒤에 `?pace=slow` 를 붙이면 4단계 표시가 천천히 진행됩니다. 단계별 소요시간 표시와 측정값에는 영향이 없습니다.

### 두 기기로 돌려 볼 때

각 브라우저의 저장소는 서로 보이지 않습니다. 발급한 기기에서 "감독관 단말" 하단 "시험장 패키지 옮기기"의 "패키지 파일 저장"을 누르면 암호화된 파일이 저장되고 해제 코드가 표시됩니다. 검증할 기기에서 같은 곳에 파일과 코드를 넣고 "패키지 가져오기"를 누르면 됩니다. 파일에는 암호문과 공개키만 있고, 해제 코드는 파일과 다른 경로(메신저 등)로 보내세요. 발급을 추가했다면 다시 내보내야 합니다.

### 측정 모드로 친구들과 돌려 볼 때

감독관 단말 하단 "측정 모드"를 켜고 시작합니다. 기록하는 값은 다음과 같습니다.

- **총 소요**: 카메라는 "스캔 시작"을 누른 순간, 이미지와 붙여넣기는 QR 을 넣은 순간부터 "일치, 통과"를 누른 순간까지. 사람이 사진을 대조하는 시간이 들어갑니다.
- **기기 검증**: 서명 검증부터 미사용 확인까지 단말이 계산한 시간. 4단계 화면 표시 연출은 들어가지 않습니다.

통과한 건만 통계에 들어가고, 결과는 CSV 로 저장됩니다. 현재 방식(휴대폰을 다시 켜서 제시)과 비교하려면 그쪽 시간은 스톱워치 등으로 따로 재야 하고, 이 도구가 대신 재 주지는 않습니다. 보고할 때는 표본 수와 측정 방식을 함께 적으세요.

## 네트워크 확인

화면 상단 "검증 중 요청 0건"은 이 페이지가 검증 구간에서 만든 요청 수를 브라우저 성능 기록으로 센 값입니다. 직접 확인하려면 다음과 같이 하세요.

1. 페이지를 열고 개발자도구(F12)의 Network 탭에서 기록을 지웁니다.
2. 감독관 단말에서 QR 을 검증하고 통과 처리합니다.
3. 새 요청이 생기지 않아야 합니다. 개발자도구의 "Offline" 으로 바꾼 뒤에도 같은 결과가 나와야 합니다.

제가 Chromium(Playwright)에서 확인한 결과입니다. 사용자 기기에서 다시 확인해 주세요.

- 페이지를 처음 열 때 요청은 14건이고 모두 같은 폴더의 정적 파일(html 1개, css 1개, js 11개, 폰트 1개)입니다. 외부 주소 요청은 없습니다.
- 시험패스 발급 중 추가 요청 0건, 검증과 통과 처리 중 추가 요청 0건.
- 브라우저를 오프라인으로 바꾼 뒤에도 붙여넣기 검증, 통과 처리가 그대로 동작했습니다(`tests/e2e.cjs`).
- 페이지에는 `connect-src 'none'` 을 포함한 콘텐츠 보안 정책(CSP)이 걸려 있어 fetch, XHR, WebSocket 요청은 브라우저가 막습니다(`docs/index.html`).

## 테스트

Node 22에서 확인했고, 브라우저 테스트는 Playwright(Chromium)와 ffmpeg 가 필요합니다.

```
node tests/logic.test.cjs                              # 서명, 검증, 암호화, 패키지 옮기기, 파기 (브라우저 없음)
node tests/e2e.cjs                                     # file:// 로 연 화면에서 전체 흐름 (12개 항목)
node tests/e2e.cjs http://localhost:8000/index.html    # 서버로 연 화면
node tests/camera.cjs                                  # 가짜 카메라 영상으로 스캔 경로 확인
node tools/screenshots.cjs screenshots/desktop 1100    # 스크린샷 다시 찍기 (모바일은 400, 다크는 세 번째 인자 dark)
```

마지막으로 실행한 결과는 logic 전체 통과, e2e 12개 항목 통과(file://, http 모두), camera 통과입니다. e2e 는 오프라인 검증, 복제 QR 거절, 이미지 업로드, 보류, 변조, 다른 기기로 패키지 옮기기, 320에서 1920px 폭의 가로 스크롤, 5종 테스트, 측정 모드, 파기 후 0건을 확인합니다.


## 디자인

차분한 공공 서비스 느낌, 파랑 하나만 강조색, 큰 글씨와 넉넉한 여백, 라이트·다크 모두 지원, 400px 폭에서 확인했습니다. 한국어 글꼴은 Pretendard 를 한글 2,350자와 ASCII 로 줄여(약 450KB) 같이 넣었으므로 인터넷이 없어도 같은 모양으로 보입니다. 사진은 일러스트이거나 직접 올린 이미지이고, 올린 사진은 이 브라우저 밖으로 나가지 않습니다. 정부 로고나 마크는 쓰지 않았습니다.

## AI 활용 고지

이 PoC 의 코드, 테스트, 문서는 Anthropic Claude(Claude Code)로 작성했습니다. 공모전 서류에도 같은 사실을 적어야 합니다.
